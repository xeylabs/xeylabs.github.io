002 / BUILD 29.09.2026 OLEH XEY LABS 8 MENIT BACA

Memantapkan Mythic.

Entri ini mencatat satu pekan kerja di Mythic dalam satu tarikan: dua item roadmap M1 dan satu pass pemantapan yang digerakkan pengujian adversarial terhadap server kami sendiri. Pengujian menghasilkan dua belas temuan; semuanya diperbaiki, masing-masing dipin regression test, dan setiap fix diverifikasi ulang dengan reproduksi aslinya sebelum disebut selesai.

Rotasi kunci tanpa downtime (ADR-0006)

Sampai pekan ini Mythic menandatangani setiap token keputusan dengan satu kunci Ed25519; merotasinya berarti restart dan membatalkan semua token yang masih hidup. Server kini memegang key ring dengan tepat satu signer aktif. Rotasi berbasis waktu dan berjalan in-process (MYTHIC_KEY_MAX_AGE, default 720h); kunci retired tetap teriklan di JWKS selama MYTHIC_KEY_RETENTION (default 24h) — lebih lama daripada usia maksimum token yang pernah ditandatanganinya. Keystore berupa file JSON yang ditulis atomik; file seed legacy 32-byte tetap bisa dimuat dan bermigrasi saat simpan pertama. Origin tetap memverifikasi token secara lokal, memilih kunci lewat klaim kid.

Store: Redis untuk multi-node (ADR-0009)

Store in-memory mengikat mythicd ke satu node. MYTHIC_STORE=redis memilih backend Redis: challenge single-use via GETDEL (ambil-dan-hapus atomik) dan counter tekanan sebagai sorted set yang dipangkas satu script Lua. Kedua backend mengimplementasikan counter sliding-window, yang menutup boundary burst jendela tetap. Interface Store kini mengembalikan error: Redis yang tak terjangkau menolak startup, dan outage saat runtime muncul sebagai 503 store_unavailable di /v1 sementara /healthz tetap terbuka untuk load balancer. Satu contract suite bersama dijalankan terhadap kedua backend (memory dan miniredis) agar semantiknya tidak bisa berbeda.

Satu catatan, tertulis: store dibagi, kunci penandatanganan tidak. Token dari node A tidak terverifikasi lewat JWKS node B. Verifikasi token lintas node membutuhkan shared keystore (KMS/HSM) — M5, tidak diselesaikan oleh perubahan ini.

Pass pemantapan: dua belas temuan

Pengujian adversarial — black-box terhadap server hidup, dengan konfirmasi white-box bila perlu — menghasilkan dua belas temuan. Yang penting, dikelompokkan per area:

Transport dan limit

Budget rate-limit baru dikonsumsi setelah validasi: flood invalid-JSON dan site key tak dikenal berjalan tanpa throttling (600 request di 225 req/s, nol 429). Budget kini dihitung sebelum validasi. Limiter mengunci IPv6 di /128 — satu /64 mengendalikan 2⁶⁴ identitas (5.000 request dari satu blok, nol tersentuh); counter kini mengagregasi IPv6 ke /64 (ADR-0007). Tidak ada timeout body/read/idle; klien lambat menahan koneksi tanpa batas. ReadTimeout, WriteTimeout, dan IdleTimeout kini diset.

Ekonomi challenge

Floor solve-time memodelkan worker 50rb H/s; worker crypto.subtle terukur ~400rb H/s, sehingga klien jujur ditandai implausible — dan klien mana pun bisa sekadar menunda verifikasi melewati floor. Floor kini kuantil rendah dari waktu solve jujur (2^d / (2M × 32), ADR-0008): false positive ≤ ~6% kasus terburuk, jawaban kelas GPU memicunya ~96%. Threat model menyatakan bahwa floor berbasis jam dinding tidak bisa menangkap klien yang menunda verifikasi — itu tugas lapisan behavioral (M2).

Token dan konfigurasi

Invarian terdokumentasi bahwa token tidak pernah hidup lebih lama dari challenge-nya tidak ditegakkan — token 1 jam diterbitkan dari challenge 5 detik. TokenTTL kini di-clamp ke ChallengeTTL. Tuning jahat (MYTHIC_FAST_SOLVE_PENALTY=500) membocorkan skor risiko 500 ke token ter-tanda-tangan; skor di-clamp ke 0–100 dan penalty di atas 100 menolak startup. MYTHIC_BASE_DIFFICULTY negatif menerbitkan challenge yang dipenuhi nonce apa pun; konfigurasi divalidasi saat startup dan nilai di luar rentang menolak melayani.

Penanganan state

Dua proses yang berbagi satu keystore bisa bertabrakan di file temp yang sama atau split-brain kunci penandatanganan tanpa suara; nama temp kini unik per proses dan save menolak menimpa file yang berubah sejak dimuat. Byte sisa setelah nilai JSON dulu diabaikan diam-diam; kini ditolak. Counter sliding-window menyimpan satu entri per hit — termasuk yang sudah di-rate-limit — sehingga sejuta hit dari satu identitas biayanya ~16,4 MB heap dan 595 detik CPU. Counter kini saturasi di IPLimit+1: flood yang sama biayanya +0,00 MB dan 714 ms.

Verifikasi

Setiap temuan punya reproduksi; setiap fix punya regression test (go test ./... -race, plus typecheck dan test SDK), dan setiap fix diverifikasi ulang dengan reproduksi aslinya. Yang masih terbuka terdokumentasi di threat model: solver sabar yang menunda verifikasi (M2, sinyal behavioral), serangan terdistribusi dengan identitas segar (M1, fingerprint jaringan), dan keystore per-node (M5, KMS/HSM bersama).
