M1 Complete: Network Signals, Worker Solver, Origin SDKs.

M1 is done. Four items closed in Mythic: JA4 TLS fingerprinting, ASN-based network scoring, a packaged Web Worker for proof-of-work, and origin verification helpers for Node.js and Python. Commits bc87ed9 through c7e4fc3.

JA4 fingerprinting

ADR-0010. The server reads the JA4 fingerprint from X-Mythic-JA4, set by the terminating proxy — never from the client directly, since any client-supplied value is attacker-controlled. Fingerprints are matched against known-browser JA4 patterns; a match applies a small risk discount, capped so it cannot single-handedly clear a challenge. Malformed values and prefix-only matches are rejected from the discount path entirely.

Stated limitation: JA4 is advisory. A client that parrots a real browser's fingerprint byte-for-byte is indistinguishable at this layer. The discount is small precisely because the signal is spoofable — it raises the cost of naive scripting, nothing more.

ASN scoring

Same ADR. Client IPs resolve to Autonomous System Numbers via a MaxMind GeoLite2-ASN database (MYTHIC_ASN_DB). Datacenter, hosting, and VPN-exit ASNs contribute risk; residential ISP ASNs do not. The lookup is nil-safe throughout: an empty MYTHIC_ASN_DB disables the signal cleanly, while a configured path that fails to open is fatal at startup. Misconfiguration fails closed; absence degrades silently by design — the operator chose not to enable it.

Both JA4 and ASN feed risk.Input and are evaluated in the challenge and verify paths. Contributions are capped in risk.Config and validated at startup; hostile tuning values refuse to serve.

Web Worker PoW solver

The SHA-256 grind previously ran on the main thread — at difficulty 24+ the page froze for seconds. The SDK now ships solveInWorker(), which stringifies a self-contained solver into a Blob URL and runs it off-thread. No separate worker file to deploy; no bundler plugin required. Progress callbacks fire every 2048 iterations; AbortSignal terminates the worker and revokes the URL. Where Worker is undefined (SSR, Node), it falls back to the main-thread solve() — slower, never broken.

MythicClient takes useWorker (default true) and now also auto-starts the behavioral collector on construction, attaching features to challenge hints. One client, one flow, no manual wiring.

Origin verification: Node.js and Python

Decision tokens were verifiable only in Go (server/xtoken). Origins now get native helpers:

sdk/js/src/verify.ts — parsePublicKey(x) wraps the JWKS raw key in DER SPKI; verifyToken(pub, token) checks the Ed25519 signature over raw payload bytes (no pre-hash), enforces canonical base64url re-encoding, and rejects expired tokens.

sdk/python/mythic/verify.py — same semantics via the cryptography package: parse_public_key, verify_token, TokenClaims dataclass, TokenError on any rejection.

Verified cross-language: a token minted by the Go server verifies in both. Twelve tests total (six per language) covering valid tokens, wrong keys, expiry, malformed input, bad keys, and tampered payloads.

Test results

go vet clean. go test ./... -race -count=1 green across all packages. tsc --noEmit clean, bun test 15/15. pytest 6/6. Per project rule, every new signal's bypass is documented before the signal ships — see ADR-0010 § "Bypasses".

Remaining: M2 behavioral biometrics (closes the delay-attack gap the solve-time floor cannot cover) and M5 shared keystore for cross-node token verification.
