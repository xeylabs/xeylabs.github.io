Mythic 加固。

这条记录把 Mythic 的一周工作汇总在一起：M1 路线图的两项内容，以及由针对自建服务器的 对抗性测试驱动的一轮加固。测试产出十二项发现；全部修复，每一项都由 回归测试钉住，每个修复都在宣告完成之前用原始复现步骤重新验证过。

零停机密钥轮换 (ADR-0006)

到本周为止，Mythic 用单一 Ed25519 密钥签署所有决策令牌；轮换意味着 重启，并使所有在途令牌失效。服务器现在持有一个只含一名活跃签名者的 密钥环。轮换基于时间并在进程内运行 （MYTHIC_KEY_MAX_AGE，默认 720h）；退役密钥在 MYTHIC_KEY_RETENTION（默认 24h）内继续出现在 JWKS 中 —— 比它们签发的任何令牌的可能寿命都长。密钥库是原子写入的 JSON 文件；旧版 32 字节种子文件仍可加载并在首次保存时迁移。源站照旧 本地验证令牌，按 kid 声明选择密钥。

存储：面向多节点的 Redis (ADR-0009)

内存存储曾把 mythicd 绑定在单节点上。 MYTHIC_STORE=redis 选择 Redis 后端：单次使用挑战通过 GETDEL（原子的取回并删除），压力计数器为由一个 Lua 脚本修剪的有序集合。两个后端都实现了滑动窗口计数器，关闭了固定 窗口的边界突发。Store 接口现在返回错误：不可达的 Redis 拒绝启动，运行时中断在 /v1 上表现为 503 store_unavailable，而 /healthz 对负载均衡器保持开放。共享契约套件对两个后端（memory 与 miniredis）运行，使它们的语义无法漂移。

一条书面说明：共享的是存储，不是签名密钥。节点 A 的令牌无法用 节点 B 的 JWKS 验证。多节点令牌验证需要共享密钥库（KMS/HSM） —— 属于 M5，本次变更并未解决。

加固：十二项发现

对抗性测试 —— 对真实服务器的黑盒测试，辅以白盒确认 —— 产出了 十二项发现。主要的按领域分组：

传输与限流

限流预算此前只在校验之后消耗：无效 JSON 与未知站点密钥的洪流 完全不受限（225 req/s 下 600 个请求，零 429）。预算现在在 校验之前计数。限流器按 /128 键控 IPv6 —— 单个 /64 拥有 2⁶⁴ 个 身份（从一个块发出 5,000 个请求，零命中）；计数器现在把 IPv6 聚合到 /64 （ADR-0007）。 此前没有主体/读/空闲超时；慢客户端可以无限期占住连接。现已设置 ReadTimeout、WriteTimeout 与 IdleTimeout。

挑战经济学

解题时间下限按 5 万 H/s 的 worker 建模；实测 crypto.subtle worker 约 40 万 H/s，诚实客户端被 标记为不合理 —— 而任何客户端都可以简单地把验证推迟过下限。下限 现在是诚实解题时间的低分位 （2^d / (2M × 32)， ADR-0008）： 误报最坏 ≤ ~6%，GPU 级答案约 96% 触发。威胁模型明确写道：墙上 时钟下限抓不到推迟验证的客户端 —— 那是行为层（M2）的工作。

令牌与配置

令牌活得不会比挑战更久这条文档化的不变式此前未被强制 —— 从 5 秒 挑战签发了 1 小时令牌。TokenTTL 现在钳制到 ChallengeTTL。恶意调参 （MYTHIC_FAST_SOLVE_PENALTY=500）把 500 的风险分值 泄漏进签名令牌；分值钳制到 0–100，超过 100 的惩罚拒绝启动。负的 MYTHIC_BASE_DIFFICULTY 会发出任意 nonce 都能满足的 挑战；配置在启动时校验，越界值拒绝服务。变异测试套件在首次 运行中还抓到一项发现：Go 的 base64 解码器会静默丢弃尾字符中 未使用的低位比特，导致不同的令牌字符串解码出相同的字节并通过 验证 —— 破坏了字符串层面的令牌身份。VerifyToken 现在强制规范 base64：解码后重新编码必须与输入完全一致，否则 拒绝令牌。

状态处理

共享同一密钥库的两个进程会在同一临时文件上冲突，或无声地脑裂签名 密钥；临时名改为进程唯一，保存拒绝覆盖加载之后被改动的文件。 JSON 值之后的尾部字节曾被默默忽略；现在被拒绝。滑动窗口计数器 每次命中存一条记录 —— 包括被限流的 —— 因此来自单一身份的一百万次 命中耗费约 16.4 MB 堆内存与 595 秒 CPU。计数器现在在 IPLimit+1 饱和：同样的洪流耗费 +0.00 MB 与 714 毫秒。

验证

每项发现都有复现步骤；每个修复都有回归测试 （go test ./... -race，外加 SDK 的类型检查与测试）， 且每个修复都用原始复现重新验证过。尚未解决的部分记录在威胁模型 中：推迟验证的耐心求解器（M2，行为信号），使用新鲜身份的分布式 攻击（M1，网络指纹），以及按节点的密钥库（M5，共享 KMS/HSM）。
